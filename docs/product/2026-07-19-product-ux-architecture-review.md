# Infini-Transeon 产品、体验与架构审查

**日期：** 2026-07-19
**状态：** 前端与后端实施计划的权威输入
**产品原则：** 配置一次，游戏期间不做决定；需要时再进入工作台深度调整。

## 1. 审查结论

产品方向可行，但旧总计划和部分原型仍混有过时规则。初始公开版本应保留全部已确认能力，同时通过渐进披露避免把自由度变成复杂度。

最重要的体验约束如下：

1. 游戏运行期间不得出现模态窗口、逐句候选选择或抢焦点界面。
2. 每个区域可以配置 1–4 个翻译通道；多个通道的结果自动并行显示，用户无需逐句选择。
3. 用户选择的是长期使用的翻译器与显示模式，不是每一句的“最佳候选”。
4. 普通翻译 API 和 LLM 都可作为初次翻译器；任一通道之后都可选择最多 2 个明确的 LLM 二次润色步骤，但禁止循环。
5. 游戏期间切换翻译器只能通过有明确目标作用域的全局热键或非激活托盘操作完成；切换后自动重译当前可见文本。
6. 所有错误和性能降级必须记录并可见，但默认通过托盘徽标、状态页和短暂非激活提示呈现，不遮挡主要游戏内容。
7. 高级自由度放入档案和区域工作台；首次设置只要求完成可运行的最小路径。

## 2. 旧计划与原型中必须修正的冲突

| 优先级 | 冲突 | 最终规则 |
|---|---|---|
| P0 | 旧计划只支持一个活动应用 | 初始公开版本支持多个窗口、显示器和桌面固定区域同时运行 |
| P0 | 翻译链原型要求用户选择候选后覆盖 | 游戏内不选择；多翻译器结果按预设布局自动同时显示 |
| P0 | 原型将 LLM “评审”作为候选选择器 | 删除 LLM 评审；LLM 只承担直接翻译或明确的二次润色 |
| P0 | 旧计划把 NMT 固定为第一阶段 | 每条翻译通道的初始翻译器可为 NMT、LLM、兼容接口或 REST 适配器 |
| P0 | 旧计划把本地模型作为默认下载内容 | 本地翻译是较低优先级能力；模型只能在用户明确请求后下载 |
| P1 | 原型主题只提供浅色/深色 | 正式产品提供跟随系统、浅色、深色，并支持高对比度和减少动画 |
| P1 | 多个原型使用 8–10 px 辅助文字 | 正式 WinUI 使用可缩放排版；常规正文至少 14 epx，辅助信息至少 12 epx |
| P1 | 原型使用可点击 `div`、缺少焦点样式 | 正式实现全部使用语义控件、可见键盘焦点和完整 UI Automation 名称 |
| P1 | 覆盖样式原型使用 `transition: all` | 正式实现只动画透明度/位移并尊重“减少动画”；游戏覆盖默认不做装饰动画 |
| P1 | 历史原型的可点击候选可能被理解为改变当前游戏 | 历史只用于比较、复制和保存人工修正；不会回写已显示结果，除非明确执行“重新翻译当前文本” |

## 3. 最终用户流程

### 3.1 首次启动

1. 选择应用语言、源语言和目标语言。
2. 添加一个可捕获目标：窗口、显示器或桌面固定区域。
3. 选择区域策略：用户绘制一个或多个区域、全窗口，或两者混合。
4. 选择 OCR 与翻译服务；在此处输入用户自己的 API 凭据。
5. 运行真实 OCR、翻译延迟和覆盖效果测试。
6. 保存档案并开始翻译。

向导不展示模型阈值、队列深度、缓存键或执行提供程序。测试失败必须停留在当前步骤并提供明确修复操作。

### 3.2 日常启动

档案中心显示最近使用、当前可匹配窗口、区域数量、语言方向和服务健康状态。用户点击“开始”后，主窗口可以关闭到托盘；运行时不要求保持设置窗口可见。

### 3.3 游戏期间

- 覆盖层不激活、不接收鼠标、不出现在任务栏或 Alt+Tab，并从捕获源中排除。
- 预设为单结果时只显示一个译文；预设为多结果时用固定槽位纵向或横向显示所有结果。
- 翻译槽位顺序、标签、颜色和布局在档案中预先设置；晚到结果不会引发布局跳动。
- 全局热键支持暂停、隐藏覆盖层、手动识别、切换翻译器组、重译当前文本和紧急退出；多目标时每个绑定明确作用于全部、前台匹配目标或指定目标组。
- 热键操作只显示短暂、非激活、自动消失的角落提示；提示不包含可点击按钮，可用热键提前隐藏。
- 普通服务错误不弹窗；持续失败以托盘徽标和可选小型状态标记呈现。状态严重度、去重、限频和恢复规则由统一矩阵定义。

### 3.4 游戏之后

历史记录按档案和原文事件分组，展示每个翻译通道的结果、来源、延迟、费用、缓存状态和润色阶段。用户可据此修改该档案或区域今后使用的翻译器，也可保存具有明确作用范围的人工修正。

## 4. 信息架构

### 4.1 配置档案中心

- 新建、导入、导出和复制档案。
- 启动、暂停和打开光学工作台。
- 显示目标匹配、服务健康与上次运行摘要。
- 不在首页暴露全部区域级高级设置。

### 4.2 设置向导

固定为四个阶段：捕获目标、语言与服务、翻译区域、测试并保存。允许保存草稿和以后继续，不创建与工作台不同步的“简化配置副本”。

### 4.3 光学工作台

- 左侧：捕获目标与区域树，支持多选、排序、复制和批量启停。
- 中央：目标预览、区域绘制、排除区、OCR 测试和覆盖预览。
- 右侧：当前选择的区域设置，按基本设置、OCR、翻译通道、覆盖样式、排版、性能与降级分组。
- 底部：单行健康状态；请求追踪、趋势和降级记录进入可展开面板或诊断页。

### 4.4 翻译通道编辑器

每个区域拥有 1–4 条独立通道，每条通道最多配置 2 个二次润色步骤：

```text
初次翻译器（NMT 或 LLM）
→ 可选的显式二次润色步骤
→ 固定显示槽位
```

每条通道可配置超时、一次有限重试、最多 2 个备用提供商、上下文权限、缓存策略和显示标签。多通道并行执行；不存在“最佳候选评审”节点，也不存在游戏内选择节点。界面在保存前显示最坏请求数、并发量、延迟和费用预算。

### 4.5 覆盖样式编辑器

每个区域可独立选择：

- 原位完全替换：新背景和新文字颜色覆盖原文。
- 半透明或模糊背景：优先保持可读性。
- 偏移区域：译文显示在预先指定的新区域。
- 浮动面板：稳定显示多个结果或长文本；可固定显示、由热键显示，或由原生引擎被动读取全局光标位置命中源框后显示，覆盖窗口始终保持鼠标穿透。

背景策略包括固定颜色、自动模糊与反差文字、时间背景缓存、半透明面板和不覆盖原文。动态背景无法保证无痕恢复，界面必须明确说明这一物理限制。

### 4.6 历史、设置和诊断

- 历史按档案隔离；默认不保存截图，只在用户启用后保存文本，并受时间和容量双重限制。持久翻译记忆是另一个独立同意项；两者均关闭时只使用内存 LRU，不向 SQLite 写入原文、译文、可逆摘要或向量。
- 设置区分应用全局默认值和档案覆盖值。
- API 密钥只以 Win32 Credential Manager 通用凭据保存；数据库仅保存凭据引用。
- 日志保存应用状态、性能、错误和降级，不保存 OCR 原文或译文。
- 没有崩溃收集服务器；默认只生成不含进程内存的本地结构化崩溃元数据。可能包含文本、图像或密钥的内存转储必须单独明确启用、显示隐私警告并短期保存。

## 5. 沉浸感合同

以下条款属于发布阻断条件：

1. 覆盖层不得抢焦点、暂停游戏、捕获鼠标或触发 Windows 激活动画。
2. 译文位置在同一原文生命周期内保持稳定；流式结果只能在预留槽位内更新。
3. 迟到结果必须通过 generation ID 丢弃，绝不能覆盖更新的游戏文本。
4. 默认不播放提示音，不使用大面积动画，不显示营销、更新或模型下载提示。
5. 更新、凭据过期和模型下载只能在非游戏主界面处理。
6. 热键冲突必须在保存时检测；所有热键均可改、可禁用。
7. 多翻译器会增加遮挡、延迟和费用，因此默认档案只启用一个通道，但用户可明确添加更多通道，每个区域最多 4 条。
8. 多结果区域必须提供最大高度、最大行数、自动缩小、滚动禁止和溢出策略；游戏内覆盖不得出现需要鼠标滚动的内容。
9. “锁定不降级”只表示系统不得主动降低该区域的用户配置；当资源或设备无法满足配置时，必须丢弃旧任务并进入显式错误或暂停状态，绝不能建立无界积压。
10. Windows.Graphics.Capture 的系统捕获边框在 Windows 11 上可通过 `IsBorderRequired = false` 关闭，但需要受信任签名的 package identity、`graphicsCaptureWithoutBorder` 能力与 `GraphicsCaptureAccess.RequestAccessAsync` 的一次性用户授权。当前 GitHub 无签名发布不伪造身份、不请求无效授权，明确显示并记录系统捕获边框会保留；接入受信任包签名后，后端平台 spike 才能实测授权、拒绝与重启持久性。任何情况下不得宣称“无痕捕获”。

## 6. 捕获、OCR 与性能策略

- 捕获目标统一为窗口、显示器和桌面固定区域。
- 区域坐标使用相对目标客户区的归一化坐标，并保存 DPI、宽高比和布局变体。
- 全窗口自动扫描使用低分辨率全局检测平面，长边默认上限 1920；小字区域通过变化驱动的原始分辨率瓦片或图像金字塔补充检测，随后只对变化的高分辨率小块执行 OCR。
- 已知区域和已跟踪文本框用更高频率进行轻量变化检测；未知区域的全局文本检测默认约 1 Hz，可由用户调整。
- 不周期性对完整 4K 帧执行完整 OCR。
- 每个阶段使用有界 latest-wins 队列；字幕 P0 不得在旧任务后排队。
- 资源治理按区域优先级降低频率、暂停低优先级自动扫描或切换模型；用户锁定区域的频率、质量和模型不被自动修改，不可满足时明确暂停或报错。
- 所有降级都记录开始、原因、影响、恢复条件和结束时间。

初始性能目标：闲置 CPU <1%，未变化画面 CPU <2%，覆盖渲染 P95 <2 ms，缓存命中 P95 <10 ms，P0 区域本机未缓存路径（变化检测→OCR→翻译请求发出，不含提供商网络延迟）P95 <300 ms，无本地翻译模型时内存 <400 MB。在线提供商网络延迟只作为分段观察指标，不作为应用可控制的硬门槛。所有数值必须附基准机器、目标数量、分辨率、采样窗口和 P50/P95/P99；完成硬件矩阵校准前只能称为候选门槛。

## 7. 技术架构结论

### 7.1 推荐栈

- C# / .NET 10 LTS / WinUI 3：应用外壳、设置、档案、翻译编排、在线提供商、worker 监督、历史与诊断。在线适配器保留模块边界，但第一版不建立单独提供商进程。
- C++20：Windows.Graphics.Capture、D3D11 图像处理、变化检测、OCR 调度、DirectComposition/Direct2D/DirectWrite 覆盖渲染。
- Windows App SDK 2.2 stable；最低平台为 Windows 11 x64（API 基线 build 22621/22H2），不支持 Windows 10（决策见 `docs/adr/2026-07-20-adr-002-windows-11-minimum.md`）；发布测试矩阵覆盖当前受微软支持的 Windows 11 版本，较新 API 仍必须运行时检测。
- ONNX Runtime CPU 是所有机器的基线；Windows ML/硬件执行提供程序只在兼容设备上按用户请求启用。
- SQLite 保存档案、缓存、历史索引和状态事件；密钥不进入数据库。
- 本地翻译模型在独立 worker 中运行，只有用户请求时才下载。

### 7.2 进程与边界

```text
InfiniTranseon.App.exe (.NET / WinUI 3，关闭窗口后驻留托盘)
├─ 档案、SQLite、历史、翻译编排、在线提供商、更新与诊断
├─ 受 ACL 保护的版本化命名管道
│  ├─ InfiniTranseon.EngineHost.exe
│  │  └─ InfiniTranseon.Engine.dll (C++20)
│  │     ├─ 捕获、原始帧、目标跟踪与本地 OCR
│  │     ├─ 多速率调度与 source/channel/stage generation 层级
│  │     └─ 原生覆盖层和游戏角落提示
│  └─ 可选 InfiniTranseon.ModelWorker.exe
│     └─ 用户明确下载的本地翻译模型
└─ 托盘：Shell_NotifyIcon + 隐藏消息窗口
```

完整截图留在 EngineHost。只有低频受控缩略图可以到达 App；用户明确启用云 OCR 时，带 OcrExecutionToken、同意策略版本、截止时间和尺寸上限的编码裁剪图由 EngineHost 发送给 App 内的在线适配器。严格离线模式不构造在线提供商或更新 HTTP 客户端。常规运行只有 App 与 EngineHost 两个进程；ModelWorker 只在用户启用本地翻译模型时启动。完整运行时所有权、数据流、复杂度和性能预算见 `docs/superpowers/specs/2026-07-19-runtime-architecture-design.md`。

## 8. 隐私、安全与发布

- 严格离线模式不构造在线客户端、不健康检查、不检查更新、不自动下载模型，也不静默联网备用。
- 云 OCR 默认关闭；启用时必须显示将上传图像裁剪而非仅文本。
- 可配置 REST 适配器不执行用户代码；限制为声明式请求模板、响应提取规则和受控凭据引用。
- 档案导入导出使用版本化格式，自动排除 API 密钥、历史、截图、模型、个人路径和窗口句柄。
- 产品免费开源，Apache-2.0；通过 GitHub Releases 提供安装版和便携版。发布流程生成 LICENSE、NOTICE、SBOM、源码归档和模型/字体/字典独立许可清单。
- 默认只在没有活动捕获且主界面可见时检查更新，不自动安装。当前无 Authenticode 阶段，MSI 必须由 Ed25519 签名的 canonical manifest 明确声明为 `unsigned`，应用在下载与打开前显示未知发布者警告；所有制品均验证 manifest 绑定的版本、渠道、架构、大小和 SHA-256，并保留双密钥轮换与防降级状态。未来采用 Authenticode 时再启用发布者验证。
- 初始公开版本不设社区档案浏览或下载。
- 所有已确认功能属于首个公开版本；开发阶段只作为内部垂直切片，不对外宣称 Alpha/Beta。

## 9. 无障碍与国际化发布门槛

- 应用 UI 使用 `.resw` 资源；不得在 ViewModel 或 XAML 中散落用户可见字符串。
- “应用语言”和“数字/日期格式区域”独立设置；后者默认跟随系统。日期、费用、字节数、延迟和语言名称使用所选格式区域，品牌和协议名不翻译。
- 支持跟随系统、浅色、深色、高对比度、200% 文本缩放和减少动画。
- 所有交互元素具备键盘操作、可见焦点、AutomationProperties.Name 和非颜色状态文本。
- 拖拽区域同时提供键盘坐标编辑和可撤销操作。
- 读取顺序在 1280×720、1920×1080、2560×1440、3840×2160 与 100%–300% DPI 下保持合理。
- 覆盖层本身为鼠标穿透，因此辅助技术用户可通过热键或托盘主动打开“最近译文”可访问面板；该操作会明确切换焦点并提供原文、译文、通道、时间和复制操作。

## 10. 发布前端到端验收场景

1. 在 4K 游戏窗口中配置 4 个区域和剩余窗口自动扫描，持续 30 分钟无队列增长。
2. 同时翻译两个窗口，分别使用不同档案、语言、OCR 和覆盖策略。
3. 一个字幕区域并行显示 DeepL 与 OpenAI 结果，不出现选择提示或布局跳动；等待、流式、成功、备用、超时、失败和取消都保持固定槽位。
4. 主翻译器超时，只有该通道按已配置备用策略处理，其他通道继续运行。
5. 游戏中通过热键切换翻译器组并自动重译当前文本，游戏不失去焦点。
6. 窗口跨显示器、改变 DPI、最大化、恢复和调整比例后，区域仍映射正确。
7. 严格离线模式下抓包确认零网络流量。
8. 历史和持久翻译记忆均关闭时，数据库不保存 OCR 和译文；日志始终不保存这些内容。
9. 高对比度、键盘、屏幕阅读器和 200% 文本缩放完成全流程。
10. 默认使用 CPU ONNX 基线；硬件加速执行提供程序仅在用户请求时启用，不自动下载。合成材质不可用时（远程会话、用户或策略禁用透明效果）UI 回退纯色背景。
11. 云 OCR 重试迟到、流式块乱序、切换翻译器、目标关闭和 EngineHost 重启后到达的旧结果均被 source/OCR/channel/stage execution token 与 overlay revision 层级拒绝。
12. 剩余区域自动扫描产生稳定的 TextTrackId/SourceEventId，跟踪框移动、合并、消失和重新出现时不会污染其他历史或覆盖槽位。

## 11. 审查过的原型问题

- `.superpowers/brainstorm/20260719-153620-0e3f7901/content/translation-chain-editor.html:81` 仍写有“用户选择的结果用于覆盖”，必须视为过时文案；同文件第 83、94 行也保留了旧候选选择模型。
- `.superpowers/brainstorm/20260719-153620-0e3f7901/content/supporting-screens.html:242` 实现了候选卡片选择；它只可作为历史检查演示，不得改变游戏中的当前结果。
- `.superpowers/brainstorm/20260719-153620-0e3f7901/content/fluent-workbench.html:92` 的区域树使用带点击事件的 `div`；正式 WinUI 必须替换为可访问的列表/树控件。
- `.superpowers/brainstorm/20260719-153620-0e3f7901/content/overlay-style-editor.html:25` 使用 `transition: all`，且没有减少动画分支；正式实现只允许明确的合成动画属性。
- 多个原型使用 8–10 px 文字和仅靠颜色表达状态，例如 `translation-chain-editor.html:50` 和 `supporting-screens.html:30`；正式排版和状态组件不得照搬。
- 原型没有形成完整的键盘焦点、UI Automation、动态状态播报和减少动画实现；正式产品按前端计划和自动化发布门槛补齐。

这些问题不会否定已确认的视觉方向，但原型只能作为布局参考，不能直接复制为生产 UI。
