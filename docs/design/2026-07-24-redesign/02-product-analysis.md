# 2. 产品与工作流分析

## 2.1 产品本质

Infini-Transeon 是**游戏实时翻译器**:捕获游戏画面 → OCR → 多通道翻译 → 非侵入覆盖显示。产品原则(权威文档确认):**配置一次,游戏期间不做决定**。这意味着 UI 天然分裂为两个使用时态:

- **配置时态**(应用窗口打开):建档、画区域、配通道、调样式、测效果。低频、深度、可以复杂。
- **游戏时态**(应用窗口关闭/最小化):托盘 + 全局热键 + 覆盖层。零交互面积,只有状态反馈。

当前 UI 没有为这个分裂建模——它是一个"必须一直开着的设置窗口",这是所有结构问题的根源。

## 2.2 用户画像与任务频率

单一用户类型:玩非母语游戏的玩家。按操作频率排序:

| 频率 | 任务 | 当前步数/问题 |
|---|---|---|
| 每次游戏(最高频) | 启动已有档案 → 关窗去玩 | 档案页点启动 → 跳转运行页 → **不能关窗**(关窗杀引擎) |
| 每次游戏 | 游戏中暂停/切翻译器组/手动 OCR | 仅热键可用(功能在);托盘缺失 |
| 每周数次 | 微调区域/通道/样式 | 进工作台 → 在 33 控件检查器里找目标控件 |
| 每周数次 | 游戏后查历史、修术语 | 历史无修正入口;术语表藏在档案卡溢出菜单 |
| 每月数次 | 新游戏建档 | 向导无门禁无绘制无试跑,首次成功率存疑 |
| 极低频 | 凭据/模型/更新维护 | 分散三个表面,离线模式静默耦合 |

**结论:当前导航把六个入口平铺,给"每月一次"的诊断和"每次游戏"的启动同等权重;而最高频的"启动后关窗"根本做不到。**

## 2.3 关键工作流与现结构的错位

1. **启动流错位。** 档案(实体)与运行(状态)被拆成两页,但"启动"是档案卡上的动作、状态却要切页看。运行状态本应是档案卡的一个属性。
2. **配置流断裂。** 一个档案的配置分散在:向导(初建)、工作台(区域+通道+覆盖+性能)、术语表页(词条+风格提示词)、无处安放的字号/描边/对比度(随 OverlayStyles 页删除丢失)。用户心智模型是"我的这个游戏的设置",实现却按控件类型切页。
3. **同一概念两套模型。** 区域在向导中是 `ProfileRegionDraft`(计算属性校验),在工作台是 `WorkbenchRegionItem`(命令式校验+撤销);优先级/上下文角色下拉在两处标签措辞还不一致("Scene" vs "Scene or location")。翻译器选择在向导是单 ComboBox、在工作台是多通道对话框——两种心智模型。
4. **信息层级倒挂。** 工作台检查器里,高频调整项(覆盖样式、通道)默认折叠,低频项(基本信息)默认展开;目标级设置(检测长边、剩余区域扫描)寄生在区域检查器里。
5. **反馈链缺失。** 产品要求"所有错误和性能降级可见但不遮挡游戏"(托盘徽标/状态页/短暂提示),当前诊断页是磁盘 JSONL 一次性读取的静态列表,`RecoveryAction` 硬编码 `"—"`,与实时事件流脱钩。

## 2.4 信息优先级(重设计依据)

**一眼可见(默认视图):** 引擎运行状态、每档案的可启动性(目标匹配+凭据就绪)、正在运行的目标健康度、需要用户处理的错误。
**一步可达:** 启动/停止/暂停、进入某档案的配置、最近历史。
**渐进披露:** 区域几何细节、通道润色链、覆盖高级样式、性能调参、诊断明细、模型管理。
**只在明确请求时出现:** 更新下载、模型下载、凭据录入、导入导出。

## 2.5 缺失的产品需求(向上游反馈)

以下是审计中发现、需产品层面补充定义的空白(本提案给出默认设计,标注 [假设]):

1. 历史"保存人工修正"的作用域语义(仅术语表?区域级替换规则?)——产品 §3.4 提到但无细则。本提案按"修正 → 可选转为术语表词条"设计。[假设]
2. 多档案同时运行时热键的目标作用域 UI(产品 §3.3 定义了绑定语义,无编辑器规格)。本提案在设置-热键节增加作用域列。[假设]
3. 覆盖层字号/描边/自动对比度随 OverlayStyles 页删除后的归属——本提案恢复至档案工作区"覆盖样式"节。
4. 托盘菜单的具体条目与层级——本提案在第 5 章给出规格。[假设]
5. "性能预设(Eco/Balanced/High)"与工作台逐区域性能参数的关系(谁覆盖谁)未定义。本提案按"预设为全局默认,区域锁定项不受预设影响"设计。[假设]
