# 4. 推荐方向与新信息架构

## 4.1 选定方案:B「档案即工作区」骨架 + A/C 要素移植

**为什么是 B:**
1. 本产品的复杂度集中在"单个档案内部"(目标×区域×通道×覆盖×术语),实体优先结构把复杂度收进实体边界内,是唯一从根上拆解 33 控件检查器的方案。
2. 单一 NavigationView 外壳、两态侧栏,是三案中 WinUI 实现风险最低、可访问性成本最低的。
3. 向导可直接复用工作区分节组件做"引导模式",消灭"区域被建模两次"的问题。

**从 A 借:** 托盘为一等公民(关窗 = 托盘化而非退出)、Home 以"启动"为首要动作、运行中档案的行内暂停/停止。
**从 C 借:** Home 的"活动流"面板(实时状态事件,替代静态诊断页的陈旧数据);命令面板列为远期增强(P3,非首发)。

**风险与代价(直面):**
- 两层导航的进出转场必须做对:工作区侧栏首项固定为"← 返回 Home",面包屑常显,Escape 触发返回(带脏检查)。
- 工作区级脏状态:五个配置分节共享一个 `ProfileWorkspaceStore` 的草稿与脏标记(第 7 章),避免"每节各自为政"。
- 跨档案历史对比:全局"活动"页提供跨档案历史入口,档案内历史为过滤视图,同一组件两种参数。

## 4.2 新路由树

```text
/                          Home(启动台 + 运行面板 + 活动摘要)
/onboarding                首次引导(无档案时自动进入,可跳过)
/profiles/new              新建档案引导流(全屏,分步,可存草稿)
/profiles/{id}             档案工作区(默认落到 overview)
  /profiles/{id}/overview       概览与就绪
  /profiles/{id}/capture        捕获与区域(画布)
  /profiles/{id}/channels       翻译通道
  /profiles/{id}/overlay        覆盖样式(含恢复的字号/描边/对比度)
  /profiles/{id}/language       语言与语境(术语表 + 风格提示词 + 游戏语境)
  /profiles/{id}/history        本档案历史
/activity                  活动(实时事件流 + 诊断 + 跨档案历史)
/providers                 提供商与模型(凭据、端点、本地模型、REST 适配器)
/settings                  设置(分节:外观与语言 / 热键 / 隐私与数据 / 性能 / 关于与更新)
```

深链:支持 `infinitranseon://profiles/{id}/capture` 协议激活与命令行参数 `--profile {id} --start`(托盘/快捷方式复用)。Frame 返回栈启用,Alt+左箭头 与标题栏返回按钮生效。

## 4.3 导航树(两态侧栏)

```text
[全局态]                        [工作区态](进入 /profiles/{id} 后)
🏠 Home                         ← 返回 Home(面包屑: Home / 原神)
──────────                      ▣ 概览
(运行中的档案置顶显示 ● 徽标)    ⬚ 捕获与区域
──────────                      ⇄ 翻译通道
页脚:                           ▤ 覆盖样式
📊 活动                         🈯 语言与语境
🔌 提供商                        🕘 历史
⚙ 设置
```

- 全局动作(任何页可用):标题栏运行状态胶囊(点击 → Home 运行面板)、更新 InfoBar(仅主界面可见且无活动捕获时)。
- 上下文动作:各页头部命令栏,不再用溢出菜单藏关键功能(术语表入口从档案卡溢出菜单提升为工作区分节)。
- 通知入口:托盘徽标 + Home 活动摘要;应用内不做全局通知中心(遵守"不打扰"红线)。
- 最近项/收藏:Home 档案网格按"最近使用"排序,支持置顶(Pin)。[假设:置顶为新增需求]
- 窄窗(<820px):侧栏收缩为 LeftCompact(仅图标);<600px 收为汉堡。

## 4.4 托盘(新增一等表面)

```text
托盘图标(状态染色:翻译中/暂停/需注意/停止)
├─ 暂停全部 / 恢复全部
├─ 显示/隐藏覆盖层
├─ 手动识别
├─ 切换翻译器组 ▸(档案内预设组)
├─ ────────
├─ 打开 Infini-Transeon(还原主窗)
└─ 退出(真正停止引擎并退出)
```
关窗默认托盘化(首次关窗询问一次并可在设置改);托盘菜单全部为非激活操作,不抢游戏焦点。

## 4.5 现有页面处置决定表

| 现页面/表面 | 决定 | 去向与理由 |
|---|---|---|
| ProfileCenterPage | **合并** | 并入 Home。档案卡增加运行状态与行内暂停/停止;"编辑"改为进入工作区 |
| RunningTargetsPage | **删除** | 运行控制并入 Home 运行面板 + 托盘;逐目标控制随多引擎支持落在档案卡/工作区概览 |
| OpticalWorkbenchPage | **拆分** | 画布+区域 → `capture`;通道 → `channels`;覆盖 → `overlay`;性能项按作用域归位(目标级进 capture 的目标行,区域级留检查器) |
| GlossaryPage | **拆分+移动** | 术语表与风格提示词 → 工作区 `language` 节,二者分开为并列卡片;补零词条空状态与行内编辑 |
| HistoryPage | **移动+增强** | 主体 → 工作区 `history`(按档案天然过滤);全局跨档案视图 → `activity`;增加日期分组与"保存修正"入口 |
| DiagnosticsPage | **替换** | 由静态列表替换为 `activity` 的实时事件流(内存事件总线推送)+ 可筛选严重度/作用域;导出与崩溃目录保留 |
| ServicesModelsPage | **保留+重命名** | → `providers`;端点编辑从凭据对话框提升到提供商卡行内;离线模式在页顶显示横幅说明其影响 |
| SettingsPage | **拆节** | → `settings` 分节导航(SelectorBar):外观与语言/热键/隐私与数据/性能/关于与更新;热键节增加作用域列;增设置内搜索 |
| SetupWizardPage | **重建** | → `/profiles/new` 引导流:步骤门禁、可点回退的步骤条、真实逐步探测(捕获→凭据校验→区域绘制(复用画布组件)→覆盖预览)、存草稿 |
| OverlayStylePage(已删) | **确认删除** | 字号/文字描边/自动对比度三个丢失控件恢复进 `overlay` 节;清理孤儿 `.resw` 资源 |
| ProviderCredentialDialog | **保留(瘦身)** | 只留凭据字段;端点移出;保持 OS 凭据库直写与内存清除 |
| 通道编辑 ContentDialog | **替换** | 改为 `channels` 节的行内管线编辑器(第 5 章),消灭代码后置模态 |
| CompositionErrorWindow | **保留** | 启动失败恢复窗口不变;补窗口标题本地化 |
| AppShell | **重构** | 两态侧栏、返回栈、最小窗口 960×600、自适应 PaneDisplayMode、深链路由 |

## 4.6 面包屑与搜索行为

- 面包屑仅在工作区态显示:`Home / {档案名} / {分节}`;点击任级可跳转,脏状态时触发统一保存/放弃询问。
- 全局搜索(P2,非首发):Home 顶部搜索框覆盖档案名、设置项、术语条目;设置页先行提供设置内搜索(首发)。
